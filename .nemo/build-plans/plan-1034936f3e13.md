# Build Plan: Optimize terminal-input component rendering performance

## Task
Improve the runtime performance and code quality of the animated ASCII Earth orb in `terminal-input.component.ts` by eliminating redundant computations, reusing allocations, and switching to `requestAnimationFrame`.

## Current Implementation
- Animation runs via `setInterval` every180 ms, stored as `private animationTimer: any`.
- Each frame, `renderSphere()` allocates fresh `outputBuffer` and `zBuffer`, recomputes light normalization and trig values inside the theta/phi loops, and builds HTML via repeated string concatenation.
- DOM access in `updateBoxHeight()` uses `document.querySelector(".gradient-box")` instead of Angular view references.

## File Changes
- [modify] src/app/terminal-input/terminal-input.component.ts — move invariants out of hot path, reuse buffers, switch to `requestAnimationFrame`, use array join for HTML, precompute constants, fix typing.

## Assumptions
- The visual output must remain identical (same colors, shading, dimensions, and frame timing behavior).
- Angular version and build tooling support modern TypeScript features (e.g. `number | null` typing, `@ViewChild`).
- No new dependencies will be added; optimizations are purely algorithmic and structural.

## Rollback Notes
- All changes are confined to `terminal-input.component.ts`. Revert by restoring the previous version of that file (e.g. via git). No other files are touched.

## Definition of Done
- Orb renders identically to before.
- Animation runs via `requestAnimationFrame` and pauses when the tab is hidden.
- No per-frame allocations for `outputBuffer`, `zBuffer`, or the result string array.
- Light normalization and constant trig values are computed outside the hot loops.
- `animationTimer` is strongly typed (`number | null`).
- `ng build` succeeds with no errors or new warnings.
